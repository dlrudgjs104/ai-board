# personal 모드: 혼자 하는 개인 프로젝트

> 요약: main 직접 작업, 커밋 전에 먼저 묻기(`feat: 내용`), push 는 요청 시에만.

협업이 없으므로 가볍게 운영한다. 프로젝트별 CLAUDE.md·메모리에 git 규칙이 있으면 그것이 우선이다.

## git
- main에서 바로 작업한다. 브랜치·PR을 만들지 않는다.
- 작업이 끝나면 커밋 여부를 먼저 묻고, 승인 후 `feat: 내용` 형식으로 커밋한다.
- push는 사용자가 요청할 때만 한다 (운영 배포와 연결된 프로젝트가 있다).
- force push, 히스토리 재작성은 명시적 요청 없이 하지 않는다.

## 문서
- 프로젝트에 새 문서(STATUS.md·worklog 등)를 만들지 않는다. 기록은 보드 카드와 작업 일지가 맡는다.
- 프로젝트가 이미 쓰는 문서 규약(예: 기획서 절별 변경 이력 갱신)은 그대로 유지한다.

## 보고
- 로컬 실행 방법이 정해진 프로젝트는 보고 전에 실행해서 사용자가 바로 테스트할 수 있게 한다 (프로젝트 메모리/CLAUDE.md 규칙).
