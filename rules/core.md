# core: 세션 연속성과 작업 원칙 (personal / work 공통)

프로젝트 안에 새 문서를 만들어 상태를 관리하지 않는다. 세션이 끝나도 남는 기억은 **보드 카드와 작업 일지**(기록 레포)이고, 훅이 자동으로 쌓는다.
프로젝트에 이미 정해진 문서 규약(README, 기획서 갱신 규칙 등)이 있으면 그것을 따른다.

## 세션 시작
1. 작업 대상 프로젝트 루트의 `CLAUDE.md` 가 있으면 읽는다. 없는 파일은 건너뛴다.
2. 훅이 넣어 주는 `[ai-board] 프로젝트 … 지금까지 상황` 요약(보드 카드, 최근 세션)으로 이어서 할 일을 판단한다.
3. `docs/plans/` 에 진행 중인 계획서가 이미 있으면 체크리스트 상태를 확인하고 이어서 한다.

## 작업 중
- 한 작업은 한 목적으로, 작은 단위로 끊는다. 큰 변경은 나눠서 진행한다.
- 사용자 판단이 필요한 지점에서 막히면 추측으로 진행하지 말고, 질문과 선택지를 답변에 적어 사용자에게 묻는다.

## 완료 조건
- 해당 프로젝트에 테스트·린트·빌드가 있으면 통과해야 "완료"다. 실패했거나 돌리지 못했다면 완료라고 하지 말고 사유와 함께 "미검증"으로 보고한다.
- 위험도는 `review-gate.md` 기준으로 판정한다.

## 작업 종료 시 (매번)
사용자에게는 다음 세 가지만 짧게 보고한다: 끝난 것 / 검토 필요도 / 내 판단이 필요한 것. (보고 형식은 `board.md`. 이 보고가 카드 코멘트와 작업 일지가 된다.)

## 시크릿
- `.env`, `*.pem`, `*.key`, 비밀번호·토큰·API 키는 커밋하지 않는다. 문서·로그·커밋 메시지에도 값을 적지 않는다.
- 설정 예시는 값이 빈 `.env.example` 로만 남긴다.
- 실수로 커밋했다면 지우는 것으로 끝내지 말고, 해당 키의 폐기·재발급이 필요하다고 사용자에게 알린다.
