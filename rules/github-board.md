# github-board: GitHub Projects 단일 보드 연동 (personal / work 공통, 보조 규칙)

여러 레포의 작업을 하나의 GitHub Projects 보드("AI Board")에서 본다. 보드는 **보조 수단**이다.
`gh`가 없거나 인증이 안 됐거나 보드가 설정되지 않았다면 이 절을 건너뛰고, 보드 때문에 작업을 막지 않는다. 보드 갱신에 실패하면 STATUS.md에만 반영하고 사용자에게 한 줄로 알린다.

## 상태 컬럼 ↔ STATUS.md 대응
| 보드 Status | STATUS.md | 의미 |
|---|---|---|
| Backlog | ⚪ 다음 예정 | 아직 시작 전 |
| AI작업중 | 🟡 진행 중 | AI가 작업 중 |
| 판단필요 | 🔴 사람 판단 필요 | 사람의 결정을 기다리는 중 (가장 먼저 봐야 함) |
| 검토대기 | 🟢 최근 완료 | AI는 끝냈고 사람 검토를 기다리는 중 |
| 완료 | (정리됨) | 사람이 확인함 |

## 이슈 단위
- 보드의 카드는 **레포의 이슈**다. 작업이 여러 세션에 걸치거나 사용자가 요청한 경우에만 이슈를 만든다. 사소한 수정마다 만들지 않는다.
- 이슈 제목은 "무엇을 한다" 형태로 쓰고, 본문에는 목표와 완료 조건을 적는다.
- work 모드에서는 PR 본문에 `Closes #번호`를 넣어 이슈와 연결한다.

## 사용 (설정 후)
`ai-board` 명령을 쓴다 (`~/ai-workflow/bin/ai-board`).
- 작업 시작: 이슈가 보드에 있으면 `ai-board move <이슈URL> AI작업중`
- 판단 필요: `ai-board move <이슈URL> 판단필요` 후 이슈에 질문을 코멘트로 남긴다
- 작업 종료: `ai-board move <이슈URL> 검토대기 <낮음|중간|높음>` (review-gate 기준 검토 필요도를 함께 표시)
- 새 작업 등록: `ai-board add <owner/repo> "제목" "본문" [상태] [검토필요도]` (상태 기본 Backlog)
- STATUS.md 항목에 이슈가 있으면 `(#번호)` 를 붙여 두어 다음 세션이 같은 카드를 찾게 한다.

설정이 안 되어 있으면 `~/ai-workflow/github-projects/SETUP.md` 를 사용자에게 안내한다.
