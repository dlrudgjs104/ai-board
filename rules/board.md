# board: 작업 현황을 실시간으로 보이게 하기 (personal / work 공통)

사람은 여러 프로젝트의 여러 세션을 **AI 작업 보드**(`ai-board` 대시보드) 한 화면에서 본다. 보드는 두 가지를 합쳐 보여 준다.
- **세션 활동 (자동):** 이 세션의 요청, 작업 중/입력 대기/답변 완료 상태, 수정한 파일, 커밋은 훅이 자동으로 기록한다. AI가 따로 할 일은 없다.
- **작업 현황 (AI가 관리):** 각 프로젝트의 `docs/STATUS.md`. 보드와 GitHub 현황 이슈가 이 파일을 그대로 보여 주므로 **이 파일이 정확해야 사람이 정확히 안다.**

## STATUS.md 를 고치는 시점 (세션 끝까지 미루지 않는다)
| 언제 | STATUS.md 에서 할 일 |
|---|---|
| 파일을 바꾸는 요청을 받아 시작할 때 | 🟡 진행 중에 `요청 요약 — 시작 HH:MM` 한 줄 추가 (⚪ 예정에 있던 일이면 그 줄을 🟡로 옮김) |
| 사람의 결정이 필요해 멈출 때 | 🔴 사람 판단 필요에 `질문 — 선택지 A/B, 추천` 추가 후 사용자에게 묻는다 |
| 끝냈을 때 | 🟡 줄을 🟢로 옮기고 `내용 — 커밋, 테스트 결과, 검토 필요도: 낮음/중간/높음` 형식으로 쓴다 |
| 남은 일이 생겼을 때 | ⚪ 다음 예정에 추가 |
| 사용자가 결정을 내려 줬을 때 | 해당 🔴 줄을 지우고 결정을 반영한다 |

- 매번 `최종 갱신:` 시각을 바꾼다. 한 번에 한 항목만 고치고, 다른 세션이 쓴 항목은 지우거나 고치지 않는다.
- 한 줄 수정·질문 답변처럼 파일을 바꾸지 않는 일은 적지 않는다.
- 파일을 바꿨는데 STATUS.md 를 갱신하지 않고 끝내려 하면 훅이 한 번 되돌린다. 그때는 STATUS.md 만 갱신하고 마친다.

## 세션 시작 때
- 훅이 `[ai-workflow] 프로젝트 … 지금까지 상황` 요약을 넣어 준다. 이 요약(🔴/🟡/⚪, 최근 세션)을 근거로 이어서 할 일을 판단하고, 🔴 항목이 있으면 사용자에게 먼저 한 줄로 알린다.
- 요약에 **같은 프로젝트에서 실행 중인 다른 세션**이 있으면, 그 세션이 다루는 파일을 동시에 고치지 않는다. 겹칠 것 같으면 사용자에게 먼저 묻는다. work 모드에서는 `git worktree` 로 분리하는 것을 제안한다.
- 사용자가 "남은 일", "할 일" 을 물으면 STATUS.md 의 🔴/🟡/⚪ 를 보여 준다.

## 보드·GitHub 명령 (필요할 때만)
- `ai-board list` : 모든 프로젝트·세션 현황을 터미널에서 본다
- `ai-board task "할 일"` : 이 프로젝트 ⚪ 예정에 할 일 추가 (사용자가 나중 일로 미뤄 달라고 할 때)
- GitHub 현황 이슈 동기화는 훅이 응답 끝·세션 종료 때 자동으로 한다. 직접 호출하지 않는다.

## 기록에 쓰지 않는 것
STATUS.md 와 요청 요약은 보드와 GitHub 현황 이슈(비공개 추적 레포)에 그대로 보인다.
- 비밀번호·토큰·API 키·`.env` 값, 개인정보, 고객 데이터는 쓰지 않는다.
- **work 모드:** 추적 레포가 개인 계정일 수 있다. 회사 내부 URL·서버 주소·고객사 이름은 일반적인 표현으로 바꿔 쓴다. 회사 정책상 개인 레포에 업무 기록을 남겨도 되는지 불확실하면 처음 한 번 사용자에게 묻는다.
