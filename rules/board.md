# board: GitHub Projects 보드(AI Board)에 작업이 실시간으로 보이게 하기 (personal / work 공통)

사람은 모든 프로젝트·세션의 작업을 GitHub Projects 보드 하나에서 본다. **카드 생성·이동·보고는 훅이 자동으로 한다.** AI는 `gh` 나 `ai-board` 로 카드를 직접 만들거나 옮기지 않는다.

## 훅이 하는 일 (알아만 둔다)
| 이 세션에서 일어난 일 | 보드 |
|---|---|
| 요청 후 20초 넘게 작업함 (그 전에 끝난 짧은 질문은 제외) | 이 세션의 카드 생성(첫 요청이 제목) → **AI작업중** |
| AskUserQuestion 으로 질문하거나 권한 승인을 기다림 | **판단필요** + 질문 코멘트 |
| 답변을 마침 | 마지막 줄이 질문이면 **판단필요**, 아니면 **검토대기** + 마지막 답변이 보고 코멘트로 붙음 |
| 사람이 이슈를 닫음 | **완료** |

사용자가 `#12 진행해줘`, `카드 #12` 처럼 번호를 주면 그 카드(보드에 미리 만든 할 일)가 이 세션의 카드가 된다.
홈처럼 레포가 아닌 폴더에서 시작한 세션은 요청에 적힌 프로젝트 이름(예: "coinsensor 프로젝트에서 …")으로 기록된다. 그 프로젝트 경로에서 작업한다.
**사용자가 "확인 완료", "완료 처리" 를 요청하면** 훅이 알려 준 이 세션의 카드 번호로 `ai-board close <번호>` 를 실행한다 (카드 → 완료, 이슈 닫힘).

## 그래서 AI가 지킬 것
1. **답변 끝의 보고가 그대로 카드 코멘트가 된다.** 작업을 마친 답변은 `끝난 것 / 검토 필요도: 낮음|중간|높음 / 판단이 필요한 것` 으로 끝낸다. `검토 필요도:` 값은 보드의 검토필요도 칸에 들어간다.
2. **사람의 결정이 필요하면 질문으로 끝낸다.** 선택지가 있으면 AskUserQuestion 을 쓰고, 아니면 답변의 마지막 줄을 질문(`…할까요?`)으로 쓴다. 그래야 카드가 판단필요로 간다. 결정이 필요 없는데 질문으로 끝내지 않는다.
3. **docs/STATUS.md 를 상태가 바뀔 때마다 고친다.** 다음 날 세션이 이어받는 기억이다.
   - 시작: 🟡 진행 중에 `요청 요약 — 시작 HH:MM` (⚪ 에 있던 일이면 옮김)
   - 막힘: 🔴 사람 판단 필요에 `질문 — 선택지, 추천`
   - 끝: 🟡 줄을 🟢로 옮기고 `내용 — 커밋, 테스트 결과, 검토 필요도`
   - 남은 일: ⚪ 다음 예정
   - 매번 `최종 갱신:` 시각을 바꾼다. 다른 세션이 쓴 줄은 고치지 않는다.
   - 파일을 바꾸고 STATUS.md 를 안 고치면 훅이 한 번 되돌린다. 그때는 STATUS.md 만 고치고 마친다.

## 세션 시작 때
- 훅이 `[ai-workflow] 프로젝트 … 지금까지 상황` 요약(STATUS 🔴/🟡/⚪, 이 프로젝트의 보드 카드, 최근 세션)을 넣어 준다. 이를 근거로 이어서 할 일을 판단하고, 🔴·판단필요 항목이 있으면 사용자에게 먼저 한 줄로 알린다.
- 요약에 **같은 프로젝트에서 작업 중인 다른 세션**이 있으면 그 세션이 다루는 파일을 동시에 고치지 않는다. 겹칠 것 같으면 먼저 묻는다. work 모드에서는 `git worktree` 분리를 제안한다.
- 사용자가 나중 일로 미뤄 달라고 하면 `ai-board task "할 일"` 로 Backlog 카드를 만든다 (이 명령만 직접 써도 된다).

## 기록에 쓰지 않는 것
요청 원문, 수정 파일 목록, 마지막 답변이 비공개 추적 레포의 카드에 그대로 올라간다.
- 비밀번호·토큰·API 키·`.env` 값, 개인정보, 고객 데이터를 답변과 STATUS.md 에 쓰지 않는다.
- **work 모드:** 추적 레포가 개인 계정일 수 있다. 답변 끝 보고에 회사 내부 URL·서버 주소·고객사 이름을 쓰지 않는다. 회사 정책상 개인 레포에 업무 기록을 남겨도 되는지 불확실하면 처음 한 번 사용자에게 묻는다.
