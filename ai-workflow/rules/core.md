# core: 문서 규약과 세션 연속성 (personal / work 공통)

세션이 아니라 **파일이 기억**한다. 아래 절차를 매 세션 지킨다.
프로젝트에 이미 정해진 문서 규약(README, worklog, 기획서 갱신 규칙 등)이 있으면 그것을 유지하고, 여기 규칙은 그 위에 `docs/STATUS.md`를 더하는 용도로만 적용한다.

## 세션 시작
1. 작업 대상 프로젝트 루트의 `CLAUDE.md`, `docs/STATUS.md`, `docs/worklog.md`(최근 항목)를 읽는다. 없는 파일은 건너뛴다.
2. `docs/plans/` 에 진행 중인 계획서가 있으면 체크리스트 상태를 확인하고 이어서 한다.
3. STATUS.md의 🔴 항목이 있으면 작업 전에 사용자에게 한 줄로 먼저 알린다.
4. `docs/STATUS.md`가 없으면 만들지 말고, 작업 종료 시 만들지 한 줄로 제안한다. (`~/ai-workflow/bin/ai-init <경로>` 로 일괄 생성 가능)

## 작업 중
- 한 작업은 한 목적으로, 작은 단위로 끊는다. 큰 변경은 나눠서 진행한다.
- 되돌리기 어려운 설계 선택을 했다면 `docs/decisions/NNNN-제목.md`(ADR: 맥락, 선택지, 결정, 이유)를 남긴다.
- 여러 세션에 걸칠 작업은 `docs/plans/<이름>.md`에 체크리스트로 쪼개고, 항목을 끝낼 때마다 체크한다.
- 사용자 판단이 필요한 지점에서 막히면 추측으로 진행하지 말고 STATUS.md의 🔴에 질문과 선택지를 적고 사용자에게 묻는다.

## 완료 조건
- 해당 프로젝트에 테스트·린트·빌드가 있으면 통과해야 "완료"다. 실패했거나 돌리지 못했다면 🟢가 아니라 🟡에 사유와 함께 둔다.
- 위험도는 `review-gate.md` 기준으로 판정한다.

## 작업 종료 시 (매번)
1. `docs/STATUS.md`를 갱신한다 (포맷은 `~/ai-workflow/templates/STATUS.md`).
   - `최종 갱신:` 줄을 현재 시각(YYYY-MM-DD HH:MM)으로 바꾼다.
   - 끝난 일은 🟢에 `내용 — 커밋/PR, 테스트 결과, 검토 필요도: 낮음|중간|높음` 형식으로 쓴다.
   - 사람이 확인하고 지나간 🟢 항목은 사용자가 정리하거나, 오래된 것(약 2주 이상)은 worklog로 옮긴다.
   - 항목이 없는 절은 `- (없음)` 으로 둔다.
2. `docs/worklog.md`에 날짜와 한두 줄 요약을 추가한다 (프로젝트 기존 형식을 따른다).
3. 사용자에게는 다음 세 가지만 짧게 보고한다: 끝난 것 / 검토 필요도 / 내 판단이 필요한 것.

## 시크릿
- `.env`, `*.pem`, `*.key`, 비밀번호·토큰·API 키는 커밋하지 않는다. 문서·로그·커밋 메시지에도 값을 적지 않는다.
- 설정 예시는 값이 빈 `.env.example` 로만 남긴다.
- 실수로 커밋했다면 지우는 것으로 끝내지 말고, 해당 키의 폐기·재발급이 필요하다고 사용자에게 알린다.
